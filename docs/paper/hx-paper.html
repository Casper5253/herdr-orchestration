hx: a deterministic control plane for a three-agent coding team

hx-claude (lead) · hx-codex (review, context controller) · hx-opencode (implementation) · for Casper
repo ~/Documents/Projects/herdr-orchestration 50 commits 240 unit tests ≈5 h wall clock

Abstract

Three coding agents from three vendors (Claude Code, Codex and OpenCode) already worked together as a Herdr team. Everyone picked models by hand, nobody tracked what any subscription had left, and long sessions re-sent hundreds of thousands of cached tokens per call. We built hx, a stdlib-only CLI plus two hooks and two skills, which turns routing, quota checks, task ownership, checkpointing and compaction into deterministic commands the lead calls. Models are only asked where judgment is needed.

The work was itself done by the team the tool now runs. A seven-model benchmark moved routine work off the most expensive model (Kimi K2.7, about 10× the cost per task of gpt-6-luna). A live end-to-end run compacted a worker from 310K to 31.6K tokens in the same session and resumed work on the next task. The user's own dashboard also refuted one founding assumption, that OpenCode Go limits are per model, and the design was corrected the same day. We report the architecture, the evidence for each choice, eleven bugs that only live runs exposed, and what is still unproven.

1Problem and constraints

The team has three subscriptions with separate allowances. OpenCode Go is cheap and was meant to be spent first; Claude and Codex are scarce and better at judgment. The brief asked for automatic choices of worker, model, effort and route, plus autonomous context management, while keeping the existing Herdr workflow intact, keeping every change reversible, and avoiding new infrastructure.

Two constraints shaped everything else. First, deterministic before generative: availability, quotas, retries, ownership and compaction thresholds are facts a script can read, so they should not cost a model call. Second, evidence before claims: every provider fact in this report is tagged measured, estimated or unknown, the same tags hx usage prints.

Provider audits written by the team before any design: docs/audit/codex.md opencode.md claude.md. Each fact carries one of the three tags.

2Architecture

hx is a control plane, not an agent. It has no daemon, database, broker or dashboard. Every component is a command that the lead, a hook or a worker calls, and all state is a small JSON or Markdown file.

hx usage
Headroom per pool and window, tagged by evidence quality.
hx route
Staged router: attempt cap → failure cause → pool → model ladder with fallback. Returns worker, model, effort, variant, method and a decision id.
hx task
Per-project ledger with canonical file ownership, worktree verification, session reservations and an O_EXCL lock with dead-pid stealing only.
hx checkpoint
Agent-authored state (decisions, exact errors, tests, next action) plus git facts, validated against the ledger revision.
hx context / compact
Decides and executes protected compaction of persistent workers at task boundaries.
hx ocrun
One-off OpenCode or Codex worker in its own visible PowerShell window; the result is read back and classified.
Design reviewed twice by hx-codex before code (10 binding amendments, 9979389) and again after code (10 + 3 findings, 06c4996 b4dc26f).

3Herdr orchestration and teams

Herdr gives each agent a named pane and a socket CLI. A team is three named agents: the lead (Claude), Codex and OpenCode. They exchange short structured briefs and reports with herdr agent prompt. Diffs are never pasted: the reader runs git diff itself, which keeps messages to a few lines and context small.

3.1A second team beside the first

Herdr names must be unique, and the original dev-* team was busy in another workspace. The launcher gained a -Team dev|hx prefix and a -LeadPane option that keeps an already-running Claude as lead. Trust rules were widened by name for the three agent families (Codex execpolicy rules, Claude --settings, an OpenCode config overlay), and the herdr-team skill now reads the prefix from the agent's own name.

The auto-mode classifier refused to let the lead edit agent permission files itself. Every permission change therefore ships as a reviewed install.ps1 the user runs once, and each replaced file is backed up first dc59600.

3.2Persistent panes and one-off workers

Iterative work goes to the warm persistent session; bounded work goes to a one-off worker with a per-task model. At first those workers ran headless. The user asked to see them, since a person spots an idle or stuck agent in seconds. Now every hx ocrun opens its own PowerShell window that stays open, and hx finds the run's result afterwards through opencode export or the Codex rollout.

Visible mode 145727a, Codex worker e49c297. OpenCode lists sessions per git root, so the lookup must run from the job's own directory FINDINGS 15.

3.3The confined Codex, and how it ended

Codex CLI 0.162.x shipped a Windows regression: the elevated sandbox's setup fails with helper_unknown_error: setup refresh had errors because Codex's own running helper holds a file the setup tries to re-permission (openai/codex #51634). The team ran Codex under the MXC preview sandbox instead, and Herdr commands escaped it through narrow execpolicy allow rules. 0.163.0 was released on 15 October and contains the fix (PR #51822). A side-by-side test settled it: the same workspace-write command fails on 0.162.1 and succeeds on 0.163.0. The team launcher now pins 0.163.0 for the Codex pane only, and the MXC workaround is removed from the team profile.

Fix commit is an ancestor of tag rust-v0.163.0 (202 ahead, 0 behind). Change 2c8cd53.

4Skills globalization

A skill written for one agent is invisible to the other two. The machine already had a single source, ~/.agents/pstack, whose sync.py writes every skill to ~/.claude/skills (read by Claude and OpenCode) and ~/.codex/skills. hx added two skills through that path rather than beside it:

herdr-team
The collaboration contract (brief and report formats, scope, two-round correction limit), now prefix-aware and pointing at hx.
hx-router
The lead's playbook: when to route, which model and effort, how to verify, when to compact, and what never to do.

The repo copies are the source; the installer copies them into pstack/local, runs sync.py and then sync.py --check, and aborts if the three mirrors disagree. One line in the global CLAUDE.md points every future lead at the skill. A skill is useful only if each agent actually loads it, so delivery was checked per agent (opencode debug skill, the Claude skill list) rather than assumed. That check caught a YAML bug: an unquoted description containing ": " made the loader fall back to the heading.

5Token efficiency through autonomy

Autonomy is cheap when the routine decisions cost nothing. hx answers "who, which model, how hard, and is there room" with file reads and arithmetic. The lead spends its own tokens only on scoping, reviewing diffs and resolving disagreements.

5.1Where the money actually went

The first measurement came from OpenCode's own message table, which stores a cost and token count for every assistant message. Over the seven days before this work, Kimi K2.7 accounted for $17.10 across 584 calls, re-sending about 138K cached tokens each time. Kimi had been the default persistent model.

5.2A founding assumption, refuted

The OpenCode audit read the plan docs as granting a separate allowance per model, and the first router rotated models to multiply capacity. Late in the day the user reported their dashboard: 82% of the 5-hour window and 90% of the week. Summing local spend over all models reproduces both numbers within about two points, so the limit is one shared pool of about $60 a month: $12 per 5 hours and $30 per week.

The consequence is direct. Rotation adds no capacity, so the only lever inside OpenCode is cost per useful task, and the cheapest capable model wins. The router now reads availability from the pool and skips a model only for its own quota error. With the week at 90%, routine work is already falling through to Codex's cheap model, so the "OpenCode ran out" path is now the normal path rather than a hypothetical one.

The correction was made by hx-codex rather than OpenCode, to protect what was left of the pool 6c328f2. The fact that a local estimate matched the vendor dashboard within ~2 points also validates hx usage as a measurement FINDINGS 16.

5.3Routing

Two rules carry most of the savings. A failure caused by missing context, an unclear brief or a broken tool never escalates the model, because a bigger model does not fix a bad input. And iterative work prefers the warm persistent session whenever its model is in the chosen tier, because re-reading cached context is cheaper than starting a fresh worker. The second rule came from the end-to-end run: ladder order had made the persistent glm session unreachable for medium work.

Warm-session rule 7e0ea05. Live escalation: minimax-m3 → kimi-k2.7-code after a capability failure, then kimi succeeded b2e4d01.

6.2Failure modes that only appear on real work

minimax-m3 passed the benchmark and then failed four of six real edits the same way. After reading about 35–40K tokens of context, it spent its fixed 32K reasoning budget and stopped with finish=length and zero or near-zero output. It has no variant that lowers thinking, so it was excluded. Headless runs also exited with code 0 after an API error, after an auto-rejected permission, and after a truncated stream. hx ocrun therefore judges a run by its event stream and requires a real final finish reason, never by the exit code.

FINDINGS 4 6 7 9 10. A false "permission rejected" came from matching the word inside a file the worker had read; detection now looks only at failed tool calls 7a58c09.

6.3Effort

Effort is set at dispatch and never by reconfiguring a live session. The measurements split the providers cleanly. Codex model_reasoning_effort is a real control (Luna at low effort used 155 reasoning tokens and passed). A Claude subagent's effort is a real control (Sonnet at low effort passed in 7 s). On OpenCode, glm-5.3-flash declares low, high and max but showed no consistent difference across three tasks, while gpt-6-luna exposes OpenAI's reasoning effort directly. The router therefore passes --variant only to models that declare it and otherwise expresses effort through the model tier.

7Compaction logic

Compaction is not automatically cheaper: it costs a summarisation call, breaks the warm cache and can lose detail. hx therefore compacts persistent workers only where all three risks are lowest, at a finished task boundary. Under pressure in the middle of a task, it relies on each tool's native auto-compaction instead.

The effective limit is capped at 200K tokens even for 1M-token models, because each call re-sends the whole context as cached input, so cost pressure arrives long before the native window fills. The lead is compacted by Claude Code itself. Its PreCompact hook lists active tasks and their next actions and tells the summary to keep exact error strings verbatim. Its SessionStart(compact) hook restores each active task's validated checkpoint, with the next action first.

Live result The e2e worker had grown to about 310K tokens (1.55 × the effective limit). hx compact brought it to 31.6K tokens in the same session, and the worker acknowledged the checkpoint with the nonce. Verification then failed for two reasons no unit test could see: herdr agent read returns plain text, not JSON, and OpenCode hard-wraps long replies (re- / review). The controller correctly reported compact-unknown instead of success. Both bugs were fixed and re-checked against the real pane text, where the old matcher returned False and the new one True.

10Limits and threats to validity

  • OpenCode headroom is estimated from this machine's history. It matched the dashboard today, but use from another device would not be counted, and no vendor API exposes the remaining allowance.
  • Codex and Claude headroom often read unknown: Codex refreshes only when Codex runs, and Claude only in team sessions with the status line. The router treats unknown as usable, not exhausted.
  • The lead is not compacted proactively; it relies on Claude's auto-compact and the hooks. Whether a queued /compact to the lead's own pane runs after its turn is the last open test.
  • Benchmark cells are single runs on small tasks.
  • No whole-week savings figure exists yet. That needs routing.jsonl from real use. The per-task numbers above are the evidence today.

11Findings, in order of discovery

  1. Kimi was the heavy pool: about 138K cached tokens per call.
  2. /compact through Herdr works, but Git Bash rewrites it into C:/Program Files/Git/compact.
  3. Headless OpenCode exits 0 on rejected permissions, API errors and truncated streams.
  4. deepseek models need an account privacy setting.
  5. minimax-m3 exhausts a fixed 32K reasoning budget with no output on real edits.
  6. Graders must be validated in both directions; one failed four correct answers.
  7. A catch-all in "never fail the session" hooks hid an ImportError.
  8. PowerShell 5.1 reads BOM-less UTF-8 as ANSI.
  9. Unquoted YAML descriptions break skill loading.
  10. Ladder order starved the warm persistent session.
  11. Pane text is not JSON, and TUIs hard-wrap replies.
  12. glm's declared effort variants made no measurable difference.
  13. OpenCode Go is one shared pool, not per-model allowances.
  14. Codex 0.163.0 fixes the sandbox regression; the MXC workaround is retired.
  15. On Windows, deleting a lock file races with a reader of that file; release now retries.

12Next steps

  1. After one to two weeks of use, summarise routing.jsonl by model and pool and re-tune the ladders.
  2. Make lead self-compaction proactive at task boundaries, depending on the queued-/compact test.
  3. Re-benchmark on harder multi-file tasks with three runs per cell, including gpt-6-luna at low versus medium.
  4. Log what hooks swallow; store method and model on task assign.
  5. Decide whether to enable the Global-regions setting for deepseek.
