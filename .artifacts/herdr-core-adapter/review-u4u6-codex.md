## Findings

1. **P1. `team/Start-HerdrAppTeam.ps1:129`: The promotion date is the only Devin admission check, so disabled or paid model settings still launch → validate enabled, allowed model, and free-model eligibility before any team mutation.**

   The model is copied directly from `policy.devin.models.medium` at line 44. With a future promotion end, an in-memory launcher probe set `devin.enabled=false` and `models.medium=swe-2-high-lightning`. The recorded hc run still included `-- devin --model swe-2-high-lightning`. No Devin process was started. Compare `hx/devin.py:172`, whose preflight rejects disabled, disallowed, unavailable, and non-Free models. The launcher currently bypasses those checks. The date check itself correctly refused an expired promotion in the probe, but only after starting Codex. Preflight the whole proposed launch first so a policy refusal does not leave an invisible Codex terminal.

2. **P1. `team/opencode-hc-status/index.js:69`: Any `properties.info.id` is treated as a session ID, regardless of event type → decode event-specific shapes and restrict session binding to session identities.**

   The event hook invokes `bindOnce` for every event at line 164. An in-memory probe sent `session.created` with root `root`, then `message.updated` with `{info:{id:"msg_1",sessionID:"root",role:"assistant"}}`. The binding became `msg_1`. This reproduces the defect for the synthetic message event shape; this review did not independently inspect the installed OpenCode SDK. Even unrecognized events with an `info.id` can overwrite the binding. A consumer trying to read that OpenCode session would receive a message identifier. Only use `info.id` on known session events, and read a message's `info.sessionID` when that event is relevant. Add a message-event regression case.

3. **P1. `team/Start-HerdrAppTeam.ps1:122`: A matching live name is accepted without validating its project or role identity → inspect and validate existing terminal details before reuse.**

   A probe supplied all three live names with `cwd="wrong-project"`. The launcher reported all three as already live and returned successfully. It queried no terminal details. The caller can believe a team is ready for this project while workers still operate elsewhere. Check canonical cwd against Project or DevinCwd and validate labels and expected program. Refuse conflicting identity with the terminal address and required correction. Do not silently retarget a live worker. A synthetic duplicate live name also selected the first address without error. The repository's captured hc contract says live names are unique, so duplicate names are a defensive malformed-roster case rather than a demonstrated core condition.

4. **P2. `team/Start-HerdrAppTeam.ps1:126`: Live roles bypass all pane reconciliation, so retries cannot finish a partially placed grid → reconcile pane presence for every validated role, including existing terminals.**

   Placement at lines 147 to 163 only visits `$started`. A failure after the starts, or after placing only Codex, leaves the remaining live terminals without panes. The next run places none of them. An all-live probe with no app panes made only roster and lead-label calls and returned success. If only OpenCode is missing and the reused Codex has no pane, OpenCode starts before waiting for a Codex pane that this run never creates. Keep existing valid panes in place, add missing panes in dependency order, and verify each resulting pane. Recovery should converge without restarting agents or deleting existing panes.

5. **P2. `team/opencode-hc-status/index.js:159`: Every mapped child status reaches the terminal, including idle → let the selected root own terminal completion and limit child forwarding to actionable prompts and their resolution.**

   In-memory replay of root busy followed by a known child's `session.idle` emitted a terminal idle record. The binding stayed root, but hc status falsely described the parent as idle. Child `session.error` can similarly replace the root status. The reference integration in `.artifacts/herdr-core-adapter/ref/herdr-agent-state.js` explicitly limits child forwarding to permission and question transitions. Track outstanding child prompts if several children can block at once. Add root-busy/child-idle and concurrent prompt tests.

6. **P2. `team/opencode-hc-status/index.js:145`: `boundSession` caches the last event ID rather than terminal ownership, leaving stale bindings across selection changes and process replacement → establish an active root and process ownership, then reject unrelated lifecycle updates.**

   A single-hook replay selected `new-root` through `chat.message`, then delivered `session.idle` for the previous root. The binding reverted to `root`. A second in-memory probe created a new plugin instance on the same terminal. Before its first event, the old binding and old PID remained. After its first prompt, the new instance correctly replaced the binding, but an old writer could overwrite it again by observing another session. A later `chat.message` for its cached session does not necessarily repair another writer's replacement because `bindOnce` returns early. Atomic rename prevents partial JSON; it does not resolve ownership. Define startup invalidation and reader validation of terminal/core identity and process liveness. Update selection from authoritative local selection or prompt signals. Restrict ordinary events to that root and its known descendants. Preserve started_at only for the same session ownership lifetime.

7. **P2. `team/Start-HerdrAppTeam.ps1:139`: The configurable Team value changes the required Devin permission prefix → constrain this launcher to the authorized team or explicitly provide a corresponding permission rule for each supported team.**

   With the default Team, both dry-run formatting and execution build `hc run --bg --outlive-parent --name dev-devin` in exactly the required order. There is one launch construction path, and its live recording test checks the name position. With `-Team other`, the same expression necessarily emits `--name other-devin`, so the exact dev-devin prefix is not preserved on every supported path. Do not broaden the permission rule silently.

## Test gaps and acceptance for the correction

The launcher tests execute real script logic against recording command functions. They catch argument order, missing roles, ordinary second-run idempotence, and planned grid placement. Their app roster already contains every pane before placement, and commands always succeed. Thus they do not prove missing-pane recovery, an actual keep transition, wrong-cwd refusal, expired policy before all mutations, disabled/paid model refusal, malformed roster refusal, or a placement failure followed by retry. `hc ls` and app ls also lack consistent exit-code and response-shape validation. An empty or error-shaped JSON document should not be treated as a healthy empty roster.

The plugin tests catch exact emitted records, simple activation gates, binding shape, sequential session replacement, a known child permission, and temp-then-rename calls. They do not cover message events, old-root events after selection, root busy while a child ends, late child discovery after resume, stale process ownership, non-TTY output, or failed writes and renames. The passing suite therefore coexists with the reproduced behavior failures above. Add a failing behavior test for each accepted correction, including partial failure at each placement boundary. Keep the live launcher acceptance with the lead after those deterministic checks pass.
